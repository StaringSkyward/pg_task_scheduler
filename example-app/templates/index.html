Watch work flow

Each button enqueues simulated work. Nothing leaves your machine.

Send emails queue: default

Short tasks, 1–3 s each. Pretend-sends to user-N@example.com.

Try: open the overview right away and watch Queued drop and Done climb over about half a minute.

Bulk import queue: bulk

A long task, about 2–3 minutes, in steps. Logs progress and stops cleanly when cancelled.

Try: cancel it from Running and then replay it, or stop a worker container mid-run and watch another worker pick it up.

Flaky task FAILS ON PURPOSE

This task fails on purpose, for the demo. It retries with backoff, and some runs end up dead.

Try: the Failure groups on the overview, then "Replay all…".

Scheduled digest cron: */5 * * * *

Runs every 5 minutes on its own, with no button. Created at startup.

Try: find its runs under Completed.

Guarantees you can check

What makes a Postgres-backed queue worth having. Each card explains one guarantee and lets you prove it.

Duplicate-safe enqueue

Every task has a key you choose. Enqueue the same key again (a retried request, a double-click) and you get the same task back, not a second one. The same key with a different payload is rejected.

→ key receipt:order-<n>

Try: press "Send receipt" twice; the banner shows the same task id. Then press the other button.

Exactly-once database work task: place-order

The order row and the task's completion commit in one transaction: both happen or neither does.

FAILS ON PURPOSE The first attempt crashes right after writing the row. The write rolls back, the task retries, and you still get exactly one row.

Try: each order shows 2 attempts in the admin UI, but 1 row below.

Transactional outbox

Completing a placed order also writes an order-placed message to queue_outbox, in the same transaction, so a message exists only if the order does. A relay in the app delivers each message a few seconds later (here it just logs it) and marks it published.

Try: place orders, then reload: messages go from pending to published. The crashed first attempts left no messages.
